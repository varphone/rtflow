# 从 0.2.x 迁移到 0.3

0.3 是布局重构（P1–P6）后的第一个版本：模块路径统一、依赖图无环、公共 API
有唯一规范路径。**绝大多数旧代码无需修改**；需要修改的项如下。

## 1. 弃用的模块/路径（0.4 移除）

| 0.2 写法 | 0.3 规范写法 | 说明 |
|---|---|---|
| `rtflow::protocol::{sdp,range,auth,rtsp,transport}` | `rtflow::rtsp::{sdp,range,auth,message,transport}` | `protocol` 仅保留为弃用门面；`rtsp::Message` 等路径不变 |
| `rtflow::protocol::transport::UpstreamTransport` | `rtflow::transport::UpstreamTransport` | 也可用 `rtflow::client::UpstreamTransport` 再导出 |
| `rtflow::proxy::{UpstreamConfig,ProxyState,StartupCacheConfig,…}` | `rtflow::mount::upstream::{…}`、`rtflow::mount::continuity::{…}` | `proxy` 仅保留为弃用门面 |
| `rtflow::proxy::UpstreamTransport` | `rtflow::transport::UpstreamTransport` | 同上 |
| `rtflow::server::{MountConfig,MountHandle,LocalPublisher,MountSnapshot,PushResult,StreamStats}` | `rtflow::mount::{…}` | 根路径 `rtflow::MountHandle` 等保持不变 |
| `rtflow::protocol_trait::{IngestProtocol,OutputProtocol}` | `rtflow::gateway::protocol::{…}` | 根再导出仍可用，但已弃用 |
| `rtflow::media_pipeline::*` | `rtflow::pipeline::*` + `rtflow::rtp::*` | 组合门面已弃用 |

以上弃用项在 0.3 仍可编译（`#[deprecated]` 警告），0.4 删除。

## 2. 迁移但源码兼容的位置

这些类型换了"规范位置"，旧路径通过再导出继续可用，**无需改代码**：

| 类型 | 0.2 位置 | 0.3 规范位置 |
|---|---|---|
| `MetricsRegistry`、`Histogram`、`MetricsEventSink` | `metrics` | `core::metrics`（`rtflow::metrics::{…}` 仍可用） |
| `Demuxer`、`DemuxedSample` | `file` | `media::demux`（`rtflow::file::{…}` 仍可用） |
| `VodSource` | `storage` | `media::vod`（`rtflow::storage::VodSource` 仍可用） |
| `SdpCrypto`、`SdpConnection` | `rtsp::sdp` | `media::{crypto,connection}`（`rtsp::sdp` 再导出不变） |
| `KeyframeCache`、`StartupCacheConfig` | `proxy` | `mount::continuity`（`proxy` 再导出不变） |

## 3. feature 语义

- `dash` 现在依赖 `hls`（DASH 复用 fMP4 分段实现）：`--features dash` 会自动启用 HLS。
- `webrtc` 现在依赖 `http`（WHEP/WHIP 端点挂在 HTTP 服务上）。
- `hmac` 改为非可选依赖（HTTP/IPC token 鉴权需要）：`--no-default-features` 构建
  不再需要额外 feature 才能编译。
- 全部 19 个 feature 均可独立 `cargo check`；新增 CI `cargo hack --each-feature`。

## 4. GStreamer（`gstreamer` feature）

`GstPlayback::register_and_play(&RtspServer)` 保留（需要 `server` feature）。
新增与协议无关的 `register_and_play_with(&MountRegistry)`，可直接挂到
RTMP/SRT/HTTP/WebRTC 共用的注册表上。

## 5. 0.2.x 已预告的 client 变更（仍适用）

- `ClientOptions`、`ClientReconnectPolicy` 标注 `#[non_exhaustive]`，crate 外
  必须用 builder 构造：

  ```rust
  let options = ClientOptions::builder()
      .transport(UpstreamTransport::TcpInterleaved)
      .build()?;
  ```

- 非 2xx RTSP 响应改为 `Error::RtspStatus { method, status }`（Display 文本不变）。
- `ClientOptions::event_sink` 与 `FrameworkEvent::Client` 事件流（0.2 已加入）。

## 6. 验证命令

```bash
cargo check --no-default-features
for f in srtp tls mp4 mkv client server file-storage metrics multicast http \
         http-flv hls ws-flv dash rtmp srt webrtc gstreamer; do
  cargo check --no-default-features --features "$f" --lib
done
cargo test --all-targets
python3 scripts/check-layering.py --baseline scripts/layering-baseline.json
```
